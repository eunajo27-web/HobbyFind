
# 📋 HobbyFind 유스케이스 문서 (Use Case Document)

## 1. 액터 정의 (Actor Definitions)

| 액터명 | 정의 및 역할 | 접근 권한 범위 |
| --- | --- | --- |
| **비회원 사용자 (Guest)** | 회원가입/로그인을 하지 않은 상태의 방문자 | 루트 페이지 및 카테고리별 페이지 탐색, 필터링 조회 |
| **회원 사용자 (User)** | 아이디/비밀번호로 가입 및 로그인한 사용자 | 탐색 기능 + 북마크 추가/해제, 마이페이지(북마크 리스트 및 통계 차트) 이용 |

## 3. 주요 단계 및 이벤트 흐름 (Main Steps and Flow of Events)

### 3.1 UC-04: 북마크 추가 및 해제 (핵심 시나리오)

1. 사용자가 루트(`/`) 또는 카테고리 페이지(`/category/[type]`)에서 취미 카드의 **북마크(하트) 아이콘**을 클릭한다.
2. 시스템은 현재 사용자의 **로그인 상태**를 확인한다.
3. **[회원인 경우]**
* 시스템은 해당 취미의 북마크 상태(등록 여부)를 반전(Toggle)시킨다.
* 데이터베이스(DB)에 북마크 정보를 반영하고, UI의 하트 아이콘 스타일을 즉시 갱신한다.


4. **[비회원인 경우]**
* 시스템은 로그인 필요 안내 메시지(Toast/Modal)를 띄우고, 로그인 페이지(`/login`)로 리다이렉트한다.



---

## 4. 대체 흐름 및 엣지 케이스 (Alternative Flows and Edge Cases)

* **비회원의 마이페이지 직접 접근 (`/mypage` URL 입력):**
* 시스템의 Auth Guard(미들웨어)가 비회원 접근을 감지하고, 로그인 페이지(`/login?redirect=/mypage`)로 강제 이동시킨다.


* **로그인 실패 (잘못된 ID/PW 입력):**
* 시스템이 인증 오류를 감지하고, 로그인 폼 하단에 빨간색 에러 메시지("아이디 또는 비밀번호가 일치하지 않습니다.")를 출력한다.


* **북마크가 0개인 상태에서의 마이페이지 조회:**
* 통계 차트에 데이터가 없음(`0%` 또는 빈 상태)을 안내하는 빈 화면(Empty State) 메시지를 노출한다.

## 5. 사전조건과 사후조건 (Preconditions and Postconditions)

| 유스케이스 | 사전조건 (Preconditions) | 사후조건 (Postconditions) |
| --- | --- | --- |
| **메인/카테고리 탐색** | 서비스 서버가 정상 작동 중이며 인터넷 연결 상태임 | 사용자가 고정된 18종의 취미 카드를 시각적으로 확인할 수 있음 |
| **로그인** | 회원가입이 완료된 상태임 | 세션이 생성되며 Top Bar가 회원 전용 메뉴(마이페이지/로그아웃)로 변경됨 |
| **북마크 등록** | 사용자가 로그인 상태여야 함 | Supabase DB의 북마크 테이블에 레코드가 추가/삭제됨 |
| **마이페이지 조회** | 사용자가 로그인 상태여야 함 | 북마크 목록과 카테고리별 분포 통계 차트가 렌더링됨 |

## 6. 비즈니스 규칙 및 제약사항 (Business Rules and Constraints)

1. **취미 데이터 고정:** 취미 목록은 운동형 6개, 지능형 6개, 예술형 6개로 총 18개 고정 항목으로 제한하며, 사용자가 임의로 추가·수정·삭제할 수 없다.
2. **인증 방식 제한:** 소셜 로그인(Google, Kakao 등)은 지원하지 않으며, 오직 **아이디·비밀번호 기반의 자체 가입/로그인**만 허용한다.
3. **추가 기능 배제:** 커뮤니티, 댓글, 상세 후기 작성, 외부 링크 연동 등의 부가 기능은 구현 범위에서 제외한다.

---

## 7. 예외 처리 절차 (Exception Handling Procedures)

* **데이터베이스 연결 지연/오류:**
* 북마크 클릭 시 DB 통신 실패 시, 사용자에게 "요청을 처리하지 못했습니다. 잠시 후 다시 시도해주세요."라는 Toast 메시지를 띄우고 UI 상태를 원래대로 롤백한다.


* **중복 회원가입 시도:**
* 이미 존재하는 아이디로 회원가입을 시도할 경우, 회원가입 폼 하단에 "이미 사용 중인 아이디입니다." 에러를 표기한다.



---

## 8. UI 고려사항 (User Interface Considerations)

* **반응형 디자인:** 모바일, 태블릿, PC 환경 모두에서 취미 카드 그리드가 유연하게 재배치(Grid Layout)되도록 설계한다.
* **Top Bar 상태 분기:**
* 비로그인 시: 로고, 카테고리 메뉴, `로그인` / `회원가입` 버튼 노출
* 로그인 시: 로고, 카테고리 메뉴, `마이페이지` / `로그아웃` 버튼 노출


* **시각적 피드백:** 북마크 아이콘 클릭 시 즉각적인 Fill/Unfill 애니메이션 또는 색상 변화를 제공한다.

---

## 9. 데이터 요구사항 및 데이터 흐름 (Data Requirements and Data Flow)

* **데이터 모델 구성:**
* `hobbies`: 취미 정보 (id, name, category) — 18개 고정 데이터
* `users`: 회원 정보 (id, username, password_hash)
* `bookmarks`: 북마크 관계 정보 (id, user_id, hobby_id)


* **데이터 흐름:**
* 클라이언트(Next.js) ➔ Supabase Auth (로그인/세션 검증) ➔ Supabase Database (북마크 조회/수정 및 통계 집계 데이터 반환) ➔ 클라이언트 렌더링



---

## 10. 보안 및 개인정보 고려사항 (Security and Privacy Considerations)

* **비밀번호 보안:** 사용자 비밀번호는 평문으로 저장하지 않고, Supabase Auth의 내장 해시 암호화 기능을 사용하여 안전하게 보호한다.
* **인증 가드 (Route Protection):** Next.js 미들웨어를 활용하여 마이페이지(`/mypage`) 등 보호된 라우트에 비회원이 직접 접근할 수 없도록 철저히 차단한다.
* **최소 정보 수집:** 본 서비스는 필수적인 아이디와 비밀번호 외에 민감한 개인정보를 수집하지 않는다.
